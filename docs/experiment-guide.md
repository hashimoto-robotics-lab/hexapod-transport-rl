# 自分で比較実験を進める

Colabの完成例を読み終えたら、次の順で自分の実験を作ります。
最初の1回は、完成例と同じランダム初期化・カリキュラム・学習設定で結果を再現します。その後に変更する項目を決めます。

## 1. 仮説を結果を見る前に書く

「何を変えると、どの指標が、なぜ変わるか」を1文にします。

例：円柱を目標へ近づける報酬の重みを20から40にすると、押す行動を選びやすくなり、同じ学習量で成功率が上がる。

逆の結果も予想します。目標付近で押し続けると、位置誤差が一度小さくなっても、停止条件を満たせない可能性があります。
学習した総報酬が増えるだけでは、運搬の性能が上がったとは判断しません。

## 2. 変えるものを1つ、固定するものを決める

最初は報酬の重み1つだけを変えます。観測・行動・報酬を同時に変えると、結果の原因を絞れません。

| 固定するもの | 完成例の設定 |
|---|---|
| 機体・歩行・接触物理 | 同じ六足ロボットと固定歩行モデル |
| 初期状態 | 共通の予定で範囲を広げ、最後は位置・向き・目標が全方向ランダム |
| 観測・行動 | 14入力、停止＋世界座標8方向、共通の回転対称化 |
| 成功条件 | 誤差5 cm未満・速度0.06 m/s未満を0.4秒保持 |
| 時間制限 | 1エピソード40秒 |
| 学習量 | 各条件・各seedで同じ総サンプル数 |
| 最適化 | 同じPPOとカリキュラム。ランダムな重み・空のAdamから開始 |
| 学習seed | 条件間で同じ組を使用 |
| 評価 | 同じbackend、同じ評価seed・回数 |

同じseedの条件間ではActorとCriticのランダムな初期重みを揃えます。
異なるseedでは初期重みと学習中の乱数を変えます。
学習が進むと選ぶ行動が変わるため、その後に経験する軌跡は異なります。

## 3. 学習中は検証、最後に独立評価を使う

`progress.json`は収集中の状態、`validations.json`は各学習時点の方策を共通の検証配置で評価した結果です。
収集中の成功数と検証成功率は、測っているものが異なります。

完成例は規定量をゼロから学習し、`checkpoint_selection="best"`で最後のランダム条件の段階の検証から方策を選びます。
検証で選んだ`selected_steps`と総学習量`trained_steps`を区別して記録します。
選択には最終評価の結果を使いません。選択基準は実験前に固定します。
完成例の検証seedは131000、最終評価seedは840000です。Colabの自分の実験は940000を使います。
最終評価を見て良かった時点やseedだけを選び直しません。
自分の新しい仮説を何度も調整する場合は、最後の報告用評価に別のseedを用意します。

## 4. 学習曲線、最終指標、動画を合わせて読む

ランダムな初期方策から学習が進み、最後の全方向ランダムの条件で標準が成功するか確認します。
簡単な開始配置での収集の成功数と、全方向の検証成功率は分けます。
1つの学習seedで結論を決めず、各seedの結果と、seed間の平均・標準偏差を示します。
同じseed同士の差を見て、初期重みを対応させて比較します。

| 見えた結果 | 次に確認するもの |
|---|---|
| 全条件で成功率0 | `demo`の短い練習か、本学習か。実際の学習サンプル数、検証曲線、終了時の距離 |
| 円柱に近づかない | 円柱への相対位置と座標系、接近に関する報酬項、実際の選択行動 |
| 近づくが押さない | 円柱へ触れているか、接近だけで報酬を得ていないか、目標への進捗 |
| 目標を通り過ぎる | 目標付近の速度、停止を含む行動、成功の保持時間 |
| 短い時間で失敗して終わる | 転倒等の失敗と終了時刻。長く行動するコストと失敗時の減点の関係 |
| 総報酬は増えたが成功率は下がった | 報酬項ごとの寄与と、成功条件との食い違い |
| seedによって優劣が逆になる | ばらつきの大きさ。事前に追加seed数を決め、全条件を追加評価する |

動画は同じ初期配置を使います。成功する動画だけを探すと、平均的な成績を説明できなくなります。
完成例の動画は事前に決めた学習seed42・動画seed850000を使っています。
動画はCPUのMuJoCo、数値評価はGPUのMuJoCo Warpです。数値計算法が異なるため、動画1本の成否をGPU評価の成功数として数えません。

## 5. 考察を「事実・解釈・限界」に分けて書く

- **事実**：成功率、距離、ばらつき、学習曲線がどう変わったか。実測値を示す。
- **解釈**：その変化は仮説と合うか。動画や報酬項の記録は、どの説明を支持するか。
- **限界**：3つの学習seed、固定した学習予算、この初期状態分布の範囲での結果であること。
- **次の実験**：解釈を確かめるため、次に1つだけ変える項目を決める。

成功率が上がらなかった実験も結果です。「効果がなかった」と断定する前に、今回の予算で学習が進んでいたか、seed間の差がどの程度だったかを確認します。
GPUの種類や他の処理の負荷で実行時間は変わります。完成例の実測時間をColab T4での所要時間として扱いません。

## 記録して提出する内容

以下をノートブックのMarkdownセルへコピーして埋めます。
Colabでは実験前の仮説を`experiment_plan.json`に保存し、最後の`REPORT`を編集すると考察を`report.md`へ保存できます。

```text
実験名：
仮説（結果を見る前）：
変更した1項目と値：
固定した条件：
学習seed・サンプル数：
検証の方法・最終評価seed・回数：
結果（全seed、平均、標準偏差、図とCSVの保存先）：
仮説と一致した点／一致しなかった点：
動画・報酬項から分かったこと：
この結果だけでは言えないこと：
次に確かめる1項目：
```

再現に必要な設定・ソース・重み・評価結果を、実験ディレクトリごと保存します。
