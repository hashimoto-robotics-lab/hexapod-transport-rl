# CPU物理・GPU更新の過去の測定

これは2026年10月7日の構成・結果です。現在の教材は[MuJoCo Warp版](warp-training.md)を使います。
以下に述べるCPU/GPUの分担は当時のものです。

Colabの「ランタイム → ランタイムのタイプを変更」でT4 GPUを選びます。
準備セルはインストール済みのCUDA対応PyTorchを維持します。
学習セルの`DEVICE`が`cuda`ならGPUで更新し、`cpu`ならCPUで更新します。

MuJoCoの物理計算、固定歩行モデル、Collectorの方策実行はCPUです。
actor・中央critic・GAE・MAPPO損失・価値正規化・ミニバッチをGPUへ置きます。
収集した経験をまとめてGPUへ送り、更新したactorの重みをCollectorへ戻します。
これにより物理計算の各ステップでCPUとGPUを往復させずに済みます。
検証では最新のactorを一度CPUへコピーして使います。ルールや教師行動は渡しません。

以前は準備セルがCPU版PyTorchを指定し、Collectorと学習更新もCPUに固定していました。
小さいネットワークではGPUへの転送・起動の負担が増えるためCPUで測定していましたが、
現在はGPUを利用できる構成です。物理計算までGPUへ移したという意味ではありません。

## 同じ設定で時間を比較

2026年10月7日、AMD EPYC 7282の2コアに限定し、CPU更新とRTX A6000によるGPU更新を順に実行しました。
PyTorch 2.11.0+cu128・TorchRL 0.14.0・NumPy 2.0.2を共通に使いました。
2世界・2台、horizon 128、ミニバッチ128、4 epochs、8,192チームステップ、学習seed 20261010です。
両方とも固定歩行モデルだけを読み、ランダムな上位方策を報酬だけで更新しました。
25ロールアウト目の6試行による検証も含みます。学習中に描画しません。

| 計算 | CPU更新 | GPU更新 |
|---|---:|---:|
| 経験収集（物理・歩行・方策・プロセス間通信） | 51.62秒 | 50.17秒 |
| 経験転送・GAE・PPO更新・重み反映 | 1.85秒 | 3.20秒 |
| 検証・ログ | 5.39秒 | 6.45秒 |
| 初期化・保存・終了など | 4.43秒 | 4.57秒 |
| 合計 | 63.29秒 | 64.39秒 |

GPU処理は更新ブロックの最後で同期して計測しました。
Pythonのimportと最初のCUDA初期化は計測外で、モデルとCollectorの作成は計測に含みます。
収集・更新・検証の計測区間では、経験収集がCPU更新で約88%、GPU更新で約84%を占めました。
この小規模設定ではGPUによる大幅な高速化は確認できませんでした。
GPUは他プロセスと共有し、各条件1回の測定です。1秒程度の合計差からCPUとGPUの優劣は判断しません。
これはGoogleホストのColabやT4での実測ではありません。Colabでは`progress.csv`に記録する時間を使ってください。
8,192ステップの比較は時間測定で、学習の成功率を示すものではありません。
CPUとGPUで同じseedを使っても、浮動小数点演算や乱数の生成先の違いで学習結果は完全には一致しません。
報酬比較の2条件は同じ学習先を使い、卒論では複数の学習seedで成功率のばらつきも報告します。

[計測区間ごとの全ログ・条件](results/gpu_training_20261007.json)を保存しています。
GPU上の実際の勾配更新、CollectorのCPU方策への重み反映、GPU保存モデルのCPUでの読み込みもテストしています。

## 標準の学習量で実行

同じRTX A6000と2 CPUコアを使い、学生用ノートブックの2条件を各65,536チームステップ学習しました。
上位方策はランダムな初期重みから開始し、参考モデル・旧モデル・デモ行動を学習へ渡していません。
難度移行の閾値は50%、学習seedは20261010、共通のテストはseed 84000から12配置です。
GPUで学習した最後のモデルをCPUへ読み込んで評価しました。
Python 3.12.13・NumPy 2.0.2・PyTorch 2.11.0+cu128を読み込み済みのローカルJupyterカーネルで、
全16コードセルを実行しました。準備セルでCUDA対応PyTorchが維持されることも確認しています。
描画はOSMesa、Git取得は編集済みソースのローカルfixtureを使い、GoogleホストのColabでは実行していません。
歩行・参考再生・2条件の学習・評価・9本のmediapy動画・ZIP保存まで約21.05分でした。
全動画を5 fpsでデコードし、移動した結果フォルダのモデル読み込みと、2条件の初期actor重みの一致を確認しました。

## 保存と再開

`run.json`に学習先・GPU名・物理計算先を記録し、checkpointにはCPUと使用したGPUの乱数状態を保存します。
`load_mappo(path)`はCPUへ読み込むため、GPUで学習したモデルもGPUなしで再生できます。
`load_mappo(path, device="cuda")`でGPUへ読み込み、optimizer・価値正規化を復元して学習を再開できます。
手順は[Colabガイド](colab-guide.md)を参照してください。
