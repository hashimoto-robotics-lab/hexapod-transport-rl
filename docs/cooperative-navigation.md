# 導入課題：協調すれ違い

学生が「複数のロボットをMAPPOで動かすと、どんな挙動を学ぶか」を短い実験で確かめるための課題です。
T押しの接触・物体回転・摩擦の学習を外し、目的地への移動と他機との間隔に集中します。
運搬の研究へ進む前に、観測・行動・共有報酬・学習・評価の関係を理解できます。

## 課題とAPI

2〜4台が半径0.95 mの円上から出発し、それぞれ反対側の目的地へ移動します。
初期配置の全体の向きはランダム、位置には±8 cm、向きには±0.2 radの揺らぎがあります。
目的地の中心から30 cm以内に全機が入り、0.8秒留まると成功です。上限は32秒です。
機体の転倒・場外は失敗です。接触しても即終了にはせず、報酬と評価で計測します。

```python
from hexapod_transport_rl import NavigationConfig, NavigationEnv

env = NavigationEnv(NavigationConfig(num_robots=2), render_mode="rgb_array_list")
observation, info = env.reset(seed=42)
observation, reward, terminated, truncated, info = env.step(action)
frames = env.render()
env.close()
```

| 項目 | 内容 |
|---|---|
| 環境 | `HexapodNavigation-v0` / `NavigationEnv` |
| 行動 | `(N,3)`、正規化した機体座標の前進・横移動・旋回、各−1〜1 |
| 自機の観測 | 目標相対XY / 1.9 m、速度XY / 0.2 m/s、直前の正規化行動3成分 |
| 他機の観測 | 相対XY / 1.9 m、速度XY / 0.2 m/s、1台につき4成分 |
| 観測の形 | `(N, 7+4*(N−1))`。2台11成分、4台19成分 |
| 座標 | 位置と速度はすべて観測する機体の座標系。他機は自機の次から循環順に並ぶ |
| 周波数 | 上位指令2.5 Hz、固定歩行25 Hz、MuJoCoとモーター200 Hz |

行動は符号ごとに歩行モデルの範囲へ変換します。前進−0.15〜0.20 m/s、横移動±0.10 m/s、旋回±0.60 rad/sです。
経路計画・回避制御・教師行動は含みません。足関節の動きだけを既存の固定モデルが担当します。
共有Actorは各機の観測からコマンドを選び、中央Criticは全機の観測を見ます。

## 報酬を変える

全機に同じチーム報酬を渡します。係数は `NavigationRewardWeights` で指定します。
`progress`は平均目標距離の減少、`distance`は残り距離の時間積分です。
`separation`は機体中心の距離が0.75 mを下回ると二乗で増えるペナルティ、`collision`は実際の機体間接触時間です。
`arrival`は目的地内の台数割合への報酬、`success`と`failure`はエピソード終了時の報酬です。
途中の時間項には `dt` を掛けます。安全項は柔らかい罰なので、安全な間隔や接触回避を保証するものではありません。

最初は標準設定を使い、その後は安全項の有無を同じseed・同じ予算で比較すると目的を理解しやすくなります。
4台へ増やすと観測とCriticの形が変わるため、2台の重みを流用せず新規学習します。
研究の評価では学習seedも複数試し、学習に使わない初期配置で到達率・接触なしの成功件数・接触時間を比較します。

学習では探索のために行動をサンプリングし、評価と動画では平均行動を使います。学習中と評価時の成功数が異なることがあります。

## 実測の読み方

2026年10月13日の2台・学習seed 42の試行では、ランダムな上位方策から学習・16例の評価・動画1本まで約242秒でした（RTX A6000）。
16/16例で到着し、接触時間は全例0秒でした。同じ先頭例のCPU版MuJoCo動画でも到着しました。
これは初期配置の向きと小さい揺らぎを変えた範囲の確認です。任意の障害物・初期配置・4台へ一般化した成績ではありません。
Colab/T4の時間、複数学習seedでの再現性、4台の学習性能は未確認です。

開発時の最初の試行は22 cmの目標範囲で、接触せずに通過しましたが到着成功は0/16でした。
その結果を受けて範囲を30 cmにし、報酬・評価が一致した新しい設定を**ゼロから**学習しました。
第2試行は標準の時間刻み補正をしたγ・λも使っているため、単一要因だけを変えた比較ではありません。
精密停止を導入の成功条件から少し緩めた変更です。両試行の結果を [実測記録](results/navigation_experiments_20261013.json) に残します。

## コードを読む順番

1. [学生用Colab](../notebooks/cooperative_navigation_colab.ipynb)：通常のimportとGym API。
2. `navigation.py`：設定、機体座標の観測、共有報酬、成功判定。
3. `training.py`：TorchRLの収集・GAE・MAPPO更新・保存。
4. `navigation_evaluation.py`：学習に使わない配置の評価と実際の25 fps動画。

GPU版の物理は `warp_navigation.py`、共通の歩行とモーターは `locomotion.py` と `warp_physics.py` です。
CPU版MuJoCoとWarpは丸め誤差で挙動が異なるため、数値評価と動画の成否は別々に保存します。
