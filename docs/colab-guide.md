# 1条件ずつ実験する

[学生用Colab](https://colab.research.google.com/github/hashimoto-robotics-lab/hexapod-transport-rl/blob/main/notebooks/hexapod_transport_rl_colab.ipynb)でT4 GPUを選びます。
公開GitHubから取得するので認証は不要です。準備・歩行・Gym APIは最初に確認し、実験では5〜8を繰り返します。

1. `PushTRewardWeights`を決め、変更による挙動の予想を書く。
2. `train_mappo()`でランダムな運搬方策から学習する。
3. 開発8配置の数値と、同じseedの25 fps動画1本を見る。
4. ZIPを保存し、別の報酬条件へ進む。

## 時間の予算

1ループは学習・数値評価・動画確認です。初回のインストールは別です。
学習の予算は360秒。環境構築・収集・GAE・更新を含みます。初回コンパイルもログに残ります。
予算はロールアウトの境界で確認するので、厳密なタイムアウトではありません。
GPUが遅ければ収集ステップ数も少なくなります。T4の所要時間は実際のログで測ります。

512世界・horizon 32・ミニバッチ1024・2 epochsを初期構成にしています。
描画は評価の動画1本だけです。物理・歩行・学習・面積・回り込みの状態評価はGPUで行います。
4台も時間予算で停止しますが、同じ時間に得られる経験と学習性能は2台とは異なります。

## 報酬と比較

`PushTRewardWeights()`は公式に対応する面積報酬だけです。
研究用に重なり率の増加、押す側への接近、成功時の報酬、時間・接触のコストを追加します。
回り込みの距離は報酬の状態評価値で、方策へ経路や教師行動を渡しません。
成功判定は両条件とも95%超です。追加項のある結果を公式報酬だけの結果とは扱いません。

短時間での成功は保証しません。最大重なり率が上がっても95%未満なら成功0件です。
全条件で同じ台数・初期配置・物理・学習seed・評価seedを使います。
時間制限ではステップ数が変わるため、効率の試験と、同一ステップ数の報酬比較を区別します。
卒論の報酬比較では 試運転で予算を決め、`steps=262144, max_seconds=None`等 等で予算を揃えます。
開発後に設定を固定し、学習seed3種類以上・未使用50配置以上で評価します。

## 保存と読むコード

`create_experiment(..., unique=True)`は再実行ごとに別のフォルダーを作り、編集したコード・資産・版を記録します。
`initial.pt`・`pusht.pt`・`run.json`・`progress.csv`・評価JSON・動画が同じフォルダーに入ります。
初期モデルには空のAdam・新しい価値統計が入り、前の条件の学習状態を引き継ぎません。
TorchRLの更新ループは[`training.py`](../src/hexapod_transport_rl/training.py)です。
旧課題の教材は[archive](../notebooks/archive/)にあり、学生の標準ノートブックとは分けています。

学生用の運搬ではXY目標を0.8秒保ちます（`high_level_decimation=20`）。標準Gym設定は0.2秒です。
歩行25 Hz・物理200 Hzは同じで、記録する動画は実際の25 Hzフレームです。
